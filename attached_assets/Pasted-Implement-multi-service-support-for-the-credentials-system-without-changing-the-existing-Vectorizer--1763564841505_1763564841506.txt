Implement multi service support for the credentials system without changing the existing Vectorizer flow. The update must work with the current backend, the Services and UserServices tables, and the subscription logic already implemented. All changes must preserve full backward compatibility.

Requirements:

Database adjustments

Add the field serviceId to the Credentials table.

serviceId must reference an existing service in the Services table.

All existing credentials must automatically receive serviceId = 1 (Vectorizer).

If a row has no serviceId, treat it as serviceId = 1.

Do not remove any existing columns.

Backend logic

Update all credential CRUD endpoints to read and write serviceId.

When listing credentials for the authenticated user, only return credentials for services the user is subscribed to.

Credentials must continue to support the existing fields: period, username, password, extra.

Maintain the current response structure so the frontend does not break.

All current Vectorizer behavior must remain identical.

Admin Panel updates

Modify the Create Credential modal to include a new field: Service (select).

Populate this select with all active services from the Services table.

Keep all existing fields exactly as they are.

When saving a credential, send serviceId in the request body.

In the Admin credentials list, add a simple label or grouping showing which service each credential belongs to.

Do not change any layout besides adding this select field.

User Panel

Do not change any visible UI elements.

Only filter credentials by serviceId so the user sees only credentials for their subscribed services.

Vectorizer users must continue seeing the credentials exactly as before. No behavioral changes in the UI.

Compatibility rules

If a credential has no serviceId in the database (old row), assume serviceId = 1.

Do not change any logic for login, payment, service activation, renewal or status handling.

The existing Vectorizer flow must remain untouched.

Avoid refactoring unrelated areas of the system.

Code organization

Keep all existing files and folders.

Adjust only the necessary modules: Credentials model, controllers, routes, admin modal component and user credential fetch logic.

Ensure all new logic is fully compatible with the multi service backend previously created.

Validation

After implementing, verify:

Admin can create Vectorizer credentials and they work normally.

Admin can create credentials for other services.

Users only see credentials for services they are subscribed to.

Existing users still see Vectorizer credentials even if old rows had no serviceId.

No UI breaks in admin or user dashboards.

Goal:
Prepare the system for multiple services using the same credential management structure, without altering any existing flows or user experience.
